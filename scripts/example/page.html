one feature, followed through the record

Automatic updates, from the plan to the release.

The plan was approved at 15:22 UTC on 9 October 2026. The release that carried it, v0.7.0, was tagged at 03:40 UTC on 10 October.

Every stop on the right is a record in this project. No session held the whole job in its head. Each one read what the last left, did its part, and wrote down what it found.

The live checks on Linux and macOS finished the next day. One step, a check on a Windows desktop, was dropped. Both are in the record too.

  1. a plan · 9 Oct, 15:22 UTC

    The plan is approved on its 38th draft.

    It was drafted in Claude Code's plan mode. Seamless kept each draft as a note and attached the reports of four planning subagents.

    Read the plan

  2. a decision

    The owner's five decisions go on file.

    Where the check runs, which installs update themselves, when the daemon may restart. A later session finds them in its briefing or with one recall.

    Open the memory

  3. {{N_STEPS}} tasks on one queue

    Parallel agents take the steps, up to seven at a time.

    Five waves ran before the release. A claim is atomic and leased, so no two agents held the same step. The first wave's handoff opens: 7 agents, 7 tasks, zero file conflicts.

    Read that handoff

  4. a research lab · {{N_TRIALS}} trials

    The risky part is tried on three operating systems first.

    Can an updater outlive the service that started it? Each trial records what the agent expected and what happened. {{N_PASS}} passed, {{N_FAIL}} failed, {{N_PARTIAL}} were partial.

    Open the lab

  5. a task

    A failed trial becomes a step. Then its premise is refuted.

    A Windows trial showed a restart leaving the daemon down. The agent that took the fix measured the real daemon and found the race came from the trial's stand-in.

    Read the step

  6. a stage · gate: human

    Thirty-four commits wait for the owner's word.

    A stage memory told every session not to push or tag until the owner chose the release point. Session after session added to it as the commits piled up.

    Open the stage

  7. a handoff · 10 Oct, 03:40 UTC

    v0.7.0 is tagged: the first release that updates itself.

    The session's handoff lists what shipped, what was tested on a Linux virtual machine, and what was still open.

    Read the handoff

  8. two runbooks

    What stays for next time.

    How to rehearse a rollback, and how to recover when an update does not apply. The next session that needs either finds it by name.

    Open a runbook

The briefing

SessionStart hook, 20 Nov 2026, in the Seamless repository

What a session is told before its first prompt.

A hook prints this when an agent starts in the repository. This one went to the session that built the page you are reading. It names rules, gates and work in a line each. The agent reads a full record only when the work comes near it.

{{BRIEFING}}
  1. the lock and the neighbors Whether the main branch is free to land on, and which other sessions have this repository open.
  2. constraints and conventions Rules an earlier session, or the owner, wrote down. Constraints are in every briefing.
  3. stages A state of the world every session must know while it holds. This one waits on a person.
  4. plans Work in flight, with what can be claimed this minute.
  5. recent findings The last sessions' handoffs, newest first.
  6. ready tasks The queue of work with no open blocker.
  7. the index A name and one line for each memory. The body is one call away.
